How booking works here

Patients book three ways — WhatsApp chat, a phone call with the voice agent, or the front desk. All three land in this one list because they write to the same database. When the AI books, it first checks the doctor's real free slots, so double-booking is impossible: two patients can never be given the same slot, even if they ask at the same second.

A missed call at a clinic is usually a patient who then calls the next clinic. Here, the moment a call rings out, the workflow starts a callback task: the voice agent rings the patient back within minutes, apologises, and can book them in on that same call. How a report travels

Lab marks the result ready → a doctor signs it off → the system sends the patient a WhatsApp message with the PDF and a two-line plain-language summary (“Your sugar levels are normal”). If the message isn't delivered — phone off, number changed — the report sits in “ready, not delivered” above and in the Overview alerts until a human sorts it out. Nothing gets lost silently.

Doctor Schedules

Booking rules per doctor, enforced by the agent on every booking

Booking mode

Time slots: the day is cut into slots and each slot holds a set number of patients; a full slot is refused and the agent offers the nearest open times. Token queue: patients are seen in order under a daily cap. A doctor with no hours saved yet is open at any hour, with only the capacity rule applying.

Weekly hours

Tick the days the doctor works and set the sessions. A second session (evening) is optional. Hours apply in time slot mode; leave days below override them.

Leave days

Bookings on a leave day are refused in both modes, and the agent offers the nearest working days.

The engine room: Temporal

Stages 3–6 can span days — book Monday, reminder Wednesday, visit Thursday, feedback Friday. Normal code forgets what it was doing when a server restarts. Temporal is a durable workflow engine: it remembers every patient's journey step-by-step and resumes exactly where it stopped, even after a crash. That reliability is the whole ballgame for appointments and reminders — and it's written as ordinary Java code in our own project, not dragged together in an outside tool.

The brain: LangGraph + Spring AI

Stage 2 is where judgement lives. The AI agent is a graph of steps — understand the message → decide: answer, book, or hand over → call a real tool (like “check free slots”) → reply. LangGraph controls those steps so the AI can't wander off-script, and Spring AI connects it to the language model. The model suggests; the graph decides; tools act. Anything risky stops for a human.

Phase 3 · Later

Where Camunda slots in

Camunda draws this same journey as a formal BPMN flowchart that a hospital manager can read and approve — “move the reminder to 2 hours before” becomes a change on a diagram, with every patient's progress visible on it and a full audit trail. It earns its place when a real hospital wants to see and govern the process. The engine room stays Temporal; Camunda becomes the glass window into it. That's why it was deliberately parked for later, not skipped.

1

Spring Boot backend

The single service you saw in the diagram. It receives messages, runs the agent, exposes the data this dashboard shows. Your stack — Java, the same skills as your day job, which is the point for your portfolio.

2

The language model

Reads a patient's messy message (“fever since yesterday, any slot tomorrow?”) and understands intent. It never touches the database directly — it asks tools to check slots or book, and the tools enforce the rules.

3

LangGraph agent

The model's chaperone. A fixed graph of steps — understand → decide → act → reply — so behaviour is predictable and testable, and a human-approval step can be inserted anywhere sensitive.

4

Temporal workflows

One workflow per patient journey. It can sleep for 3 days waiting to send a reminder, survive a server restart mid-sleep, and never double-send. This replaces n8n's job — as code, in git, unit-testable.

5

WhatsApp Business API

Meta's official way to message patients. Reminders use pre-approved “utility” templates — cheap and not treated as spam. Patients must opt in first; that's the consent field on every patient record.

6

PostgreSQL (Neon)

Every screen in this dashboard is just a view over these tables. Because the AI, the voice agent, and staff all write to the same database, the dashboard is never out of date.

Questions you'll get asked

Is any of this real patient data?

No. Every name, number, and record in this demo is fictional, generated for demonstration. That's deliberate — it makes the project safe to show publicly and portfolio-friendly, and the design keeps real patient data out of the AI's reach in production too.

Does it need the Oracle server?

No. Oracle was only one possible home for the backend. Plan A runs everything on Cloudflare Pages + Render + Neon for $0. Oracle becomes Plan B — a nicer, always-on home — whenever the instance is created.

What happens when the AI doesn't know?

It hands over to a human with a summary of the conversation, and the patient never repeats themselves. Emergencies and confused-twice conversations are hard-coded handovers, not model decisions.

Why build it in Java instead of a no-code tool?

Because the workflows live in code: versioned, tested, and licence-clean to sell. And because “durable workflows + AI agents on Spring Boot” is exactly the combination current Java job descriptions ask for.

Can a clinic actually use this?

This demo, no — it's synthetic data and simulated messaging. The Phase 2 build (real WhatsApp number, real Temporal) is the pilot version a small clinic could run.

Common tasks

The things reception does most often

Check a patient in
Appointments → find the token → Check in → Start consult → Complete visit. Billing updates automatically.
Take over a WhatsApp chat
WhatsApp Agent → open the conversation. If the patient asks for a human, the AI hands over with a summary — you don’t need to re-ask.
Follow up a low rating
Feedback → call the patient the same day. Do not send a public review request until staff have spoken to them.
Find a patient fast
Patients → search by name or condition. Check language and WhatsApp consent before messaging.

When to escalate

If a patient describes an emergency on WhatsApp or phone, the AI is set to hand over immediately — stay on the chat/call and direct them to emergency care. If a report is ready but delivery keeps failing, call the patient. If an enquiry has waited over 30 minutes, it will stay in “Needs attention” until someone replies.
